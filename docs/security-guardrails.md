## Baseline policy

`.secrets.baseline` is generated by `detect-secrets` and every current entry is marked
`is_secret: false` because it is one of:

- the documented fake local database URL/password in `.env.example` and `Makefile`;
- a deliberately synthetic test password or lab bearer token in `backend/tests`;
- the high-entropy Alembic revision identifier.

New secrets are not in the baseline and fail the hook. Review any new baseline entry; never mark a
real credential false. If a real secret is found, stop, rotate it through the operator, and refer to
its location only.

## Dependency policy

- Lockfiles (`backend/uv.lock`, `web/package-lock.json`) are committed; installs are frozen.
- `pip-audit` and `npm audit` run in CI and before release. Fix or explicitly triage with owner,
  severity, reachability, and review date; do not silently ignore HIGH/CRITICAL.
- Image scanning uses `aquasec/trivy:0.66.0`, `--ignore-unfixed`, and fails on HIGH/CRITICAL.
  Base-image fixes require rebuilding; exceptions need a documented triage entry.

## CI coverage

`.github/workflows/ci.yml` runs:

1. Backend: frozen install, Ruff, format check, mypy, 103 tests against PostgreSQL.
2. Frontend: `npm ci`, type check, production build.
3. Security: pip-audit, npm audit, Bandit, secret scan, image build, Trivy image scan.

Playwright E2E remains a documented local/release gate because it needs the lab, API, worker, and a
seeded database; it is already exercised against the deployed tailnet URL before release.

## Known limitations

- CI is unverified until the repository is pushed and the workflow runs.
- The Docker images apply distribution security upgrades (`apt-get upgrade` / `apk upgrade`)
  at build time so patched base packages are included. This trades bit-for-bit build
  reproducibility for a clean HIGH/CRITICAL scan; rebuild and rescan per release.
- Trivy's vulnerability database is downloaded at scan time; an offline runner needs a mirrored DB.
- Secret scanning cannot prove absence of secrets; it is one gate, not a guarantee.
- `COOKIE_SECURE=false` on the current plain-HTTP tailnet deployment remains a deployment caveat,
  not a code weakness. Prefer Tailscale Serve or a TLS proxy before widening access.
- Node audit has an open dev-only ReDoS advisory with no patched version in the current Vite
  dependency line (reviewed 2026-11-18). Do not mark the Security Gate clean until it is fixed
  or an owner-approved, reachability-based deferral is recorded.
